# ETOS iOS 诊断

把症状还原成**哪次输入，在谁的生命周期内，经由谁写入了什么状态，最后产生什么可见结果**。沿因果链找到首次分歧，再做可证伪干预。此方法适用于焦点、手势、异步资源、页面切换、状态同步、列表和布局；不预设框架、缓存或后端是根因。

## 核心判断

**事实先于解释。** “键盘没打开”“旧内容突然回来”“位置先下后上”是观察；“点击被挡”“缓存过期”“SwiftUI 重建”是待验证解释。分别记录实际值、预期不变量和候选原因，避免在日志里预先写入结论。

**边界先于内部。** 先对照入口、归约/派生、提交给框架、实际呈现四处的输入输出；在哪一处首次破坏预期，就向该处的生产者和写入者追。对象通知、View body 求值、数据差异、cell 生命周期和屏幕几何是不同证据，不能互相替代。

**身份、值、次序、几何分开。** 相同 ID 不保证内容相同；相同集合不保证顺序相同；相同 offset 不保证屏幕位置相同。为具体症状选择相应比较，不能只凭数量未变或回调次数多作判断。

**所有权决定有效性。** 对可疑状态问：谁拥有、谁能写、哪些是派生副本、结果在什么页面/操作范围内有效、何时撤销？检查缓存与镜像状态是否存在多个写入入口。MainActor 串行执行不等于异步返回仍属于当前页面；取消任务也不能代替对实际迟到回调的观测。

**时间与完成语义要实测。** 有序传输不保证载荷在语义上更新；await 前后的状态可能属于不同时间。确认每个 completion 承诺的是请求结束、状态写入、布局还是动画。跨线程/主机日志的输出顺序和墙钟时间也不自动构成因果顺序。

## 如何建立观测

1. 对齐源码 HEAD/dirty 与实际安装产物，记录设备、相关设置、操作和已知好/坏条件。先复用现有失败观察，不因缺少解释就反复重装。
2. 把期望写成可观察不变量，例如“页面 B 不接受 A 的资源结果”“点击后编辑状态不被无操作撤销”“无用户动作时旧内容不反复回退”。
3. 在最少的相邻边界布置成对日志：输入/来源、决策及原因、提交/丢弃、实际效果。统一单调时间、运行内关联 token 和已有生命周期身份；在事件发生处采样，异步输出只搬运已捕获值。

设计字段、选择日志出口或开始读取时，读 [日志怎么做、怎么读、怎么分析](references/logging-and-analysis.md)。该指南包括日志表、最小采样、指定文件采集、时序重建和分析示例；按症状取用，不要求每次铺满所有层。

**观测完成条件：**一次具体异常能关联到具体产物、操作和时序；或者明确还缺哪个边界。自动 fixture 未复现时，用户只执行必要动作并报告结果，agent 负责读取已授权日志，不让用户抄屏幕调试字串。

## 如何从日志走到因果

围绕一次操作缩小时间窗，找最后正常值和首次异常值，向上追接受了哪份输入/哪次写入。对照多个回合的公共前提；相同时间附近出现只是相关性，不是原因。

按证据报告候选排序与可证伪预期，再探测：若原因成立，移除或改变哪个条件应使症状消失/加重？用 gate 暂停真实 async 边界，等挂起点命中后才推进下一事件，等消费者实际生效后才观察结果。任意 sleep 或单纯加大调用频率不能替代对调用模式的控制。

优先使用真实实现加 fake 数据/传输，捕获合成生产者输出再交真实消费者。每次只改变一个条件，并用负对照排除替代解释；逐项减去非必要输入/回调/配置，保留真正让红例成立的前提。性能问题先取可比较的耗时或帧指标再干预，卡顿不直接等同布局错误。

遇到快照与事件交错、完成边界漏项或列表换序，再读 [聊天时间线门控案例](references/timeline-case.md)。它示范怎样从可见异常找到上游错误，以及如何校准 fake 和减掉多余前提；历史根因不直接套用到新问题。

**因果完成条件：**有执行过的红例、对照和指出首次错误写入的证据，或明确无法判定的缺口。记录 x/y 次实际重复；多条日志、多行候选不是多个独立试验。独立合成机制与实机原症状分别报告。

## 修复与交付判断

在真实调用接缝写正确行为的回归，先红，再做最小因果修复，最后回到原始未缩减场景。探针成功捕获坏行为可能也是 exit 0，不能当作修复绿；UI 编译通过、人工手造模型值相等也不是设备体验验证。

修复对准状态所有权、生命周期或明确框架契约；不以大范围重构、延时重试、关动画、冻结界面代替解释。确有设计边界缺失时，指出违反哪个不变量以及最小重分工，不因难定位就预设架构必须重写。

交付分开写：观察到什么、已证明什么、在哪个输入与版本上验证、原体验是否改善、仍缺什么。清理临时日志/监听器并保留必要脱敏证据；源码映射的诊断不冒充正式产物验证。

## ETOS 的操作边界

读 AGENTS.md/CONTEXT.md；涉及 Mac 再读 AGENTS.dev.md 及相关开发文档。构建安装走 scripts/ios-device.py 的固定入口和已有缓存。测试使用自有数据/fake；正常 App 观测沿当前授权范围执行，只读取约定的诊断输出。新环境、提交/推送、审查/合并和部署仍服从现有规则；本技能不扩大权限。
