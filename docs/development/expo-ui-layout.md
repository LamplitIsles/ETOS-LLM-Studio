# Expo 布局与设备验收

调整输入框、滚动区域，或在弹层中嵌套原生导航时，先追踪页面的实际视图层级和已验证的项目组件，再根据当前安装版本核对 Expo 官方 API。不要仅凭组件名称或其他页面的外层布局推断尺寸与交互。

- **宿主尺寸**：检查 React Native 与 SwiftUI/Compose 的边界由谁提供宽高。`Host` 的内容自适应或显式尺寸要与组件的固有尺寸相匹配；灵活宽度的组件需要可用宽度。输入框应有可见、可点击的尺寸，并验证输入、清空和禁用状态。参考 [Expo Host](https://docs.expo.dev/versions/v58.0.0/sdk/ui/swift-ui/host.md) 与 [RNHostView](https://docs.expo.dev/versions/v58.0.0/sdk/ui/swift-ui/rnhostview.md)，具体以项目 SDK 和安装类型为准。
- **安全区**：分别确认弹层、导航容器和键盘各自提供或消耗的空间。底部标签栏可能覆盖内容；在实际标签页的容器内获取适用的安全区，检查长内容滚到底时最后的控件可见且可操作。避免重复应用安全区或依赖固定的标签栏高度；横竖屏和键盘出现时重新核对。
- **滚动边界**：区分滚动容器的边界与内容内边距。内容可以缩进，但滚动指示器应符合页面边缘和系统惯例；检查顶部、底部及滚动到底的状态，确保控件、标签栏和键盘互不遮挡。
- **验收**：浏览器模拟和类型检查用于发现布局或逻辑问题，不能证明 iOS 原生宿主、安全区、手势或键盘表现。涉及这些行为时，在目标设备检查实际入口、分区切换、可见与可点击范围、键盘打开/关闭及滚动边界；未完成的设备检查应明确标记为待验证。
